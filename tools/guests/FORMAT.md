# Guests data format (`data/guests.json`, `data/guestlight.bin`, `data/guestground.bin`)

Generated by `tools/guests/build.py` from the baked dumps and `data/nav.bin`. Owner: `guests-data`.

## Frame and units

- Blender frame, like the walk code: `x` east, `y` north, `z` up, metres. three.js world = `(x, z, -y)`.
- `yaw` = heading about +z in radians, forward = `(cos yaw, sin yaw)` in Blender xy. In three.js an object facing
  `yaw` has `rotation.y = yaw` if its model faces +x (three's `+x`), or `yaw - PI/2` if the model faces three's `-z`.
- Coordinates are rounded to centimetres, angles to milliradians.

## `guests.json`

```js
{
  "version": 1, "frame": "blender",
  "pois":  [ { "type", "x", "y", "z", "yaw", "land", "cap", ...optional fields } ],
  "light": { "file": "guestlight.bin", "w", "h", "x0", "y0", "cell", "range", "bytes" },
  "ground": { "file": "guestground.bin", "w", "h", "x0", "y0", "cell", "classes": [names...], "bytes" },   // when present
  "paths": [ ... ]                                                                                         // when present
}
```

### Common POI fields

| key | meaning |
|---|---|
| `type` | `bench`, `stall`, `queue`, `view`, `photo`, `stage`, `table` |
| `x`, `y`, `z` | see the type below. For standing types `z` is the walk-grid height at the spot (feet). |
| `yaw` | the direction the guest faces when using the POI |
| `land` | `core` (lake, Shore Promenade, Spire), `transit` (East Gate, Lamplighters' Walk, the green gaps, Ring Promenade outside lands) or a land id (`guildhollow`, `frostmere`, `meridian`, `wanderers`, `brinewatch`, `lantern-row`, `rosewick`) |
| `cap` | how many guests can use it at once (seats; queue places; standing places) |
| `name` | human-readable name where one exists (optional) |

Every standing spot (and every bench/stall approach point) was checked against `nav.bin`: the cell and its
neighbours within 0.25 m are walkable at a height within 0.4 m of the expected foot height, and `nav.bin` only
contains cells connected to the main walkable component.

### `bench`

Benches, chairs, bleacher tiers.

| key | meaning |
|---|---|
| `x`, `y`, `z` | centre of the seat surface, `z` = top of the seat (hip height of a sitter; the seat height above the floor is `z - nav height at (ax, ay)`, usually 0.42–0.50 m; Meridian's plaza benches are only 0.10 m high, they are modelled that way) |
| `yaw` | direction a sitter faces (away from the backrest; for backless benches the side with knee room / walkable ground) |
| `cap` | number of seats: seat `k` (0..cap-1) sits at `(x, y) + r * ((k + 0.5) / cap - 0.5) * len`, where `r = (sin yaw, -cos yaw)` (the sitter's right) |
| `len` | usable length along the bench (m) |
| `ax`, `ay` | approach point: walkable spot in front of the seat where a guest stands before sitting down (feet at the walk-grid height there) |

## `guestlight.bin`

gzip of a `w * h * 4` byte grid, row-major, row `j` = `y0 + (j + 0.5) * cell` (y increasing northwards), column
`i` = `x0 + (i + 0.5) * cell`. Each cell is RGBM8 like the park meshes: `hdr = rgb / 255 * (a / 255) * range`
(`range` = 32, same as `manifest.range`); linear light. Cells further than 2 m from any walkable cell are 0 (black);
sample with bilinear filtering (cell centres as above).

Meaning: the baked irradiance (light before albedo, moon EXCLUDED: the viewer adds moonlight itself) arriving at the
ground where a guest stands. To light a guest like the park's surfaces: `colour = albedo * hdr (+ the viewer's moon
term) + emission`. Values: median 0.05, 90th percentile 0.14, 99th 0.33 (max channel) on walkable cells.

Level A (ground) only: on the few upper-level cells (bridges, decks) the grid holds the ground below.
